## 3. Решение для протокола (обсудить на паре)

**Transaction ID: генерируется системой или вводится пользователем?**

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Системный `TX-000123`** (сейчас в приложении) | Дубликат невозможен по построению; совпадает с Task 7 («generated automatically»); ничего не надо валидировать в форме | Нельзя сослаться на номер чека |
| **Ручной `TX-100`** (как в reference build Нурбола) | Можно вписать номер чека | Нужна проверка уникальности, риск дублей, лишнее поле в форме |

Рекомендация: оставить системный ID, а номер чека (если нужен) хранить отдельным
необязательным полем `receipt_no`. Тогда TC-F-10 снимается как «не применим», а
уникальность остаётся гарантией базы.
