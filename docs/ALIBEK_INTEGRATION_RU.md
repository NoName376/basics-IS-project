# Интеграция с базой Алибека — разбор и план

**Дата:** 02.11.2026 · **Файлы:** `schema.sql`, `data.sql`, строка подключения из Telegram

---

## 1. Что пришло

| Файл | Содержимое |
|---|---|
| `schema.sql` | 3 таблицы (`users`, `categories`, `transactions`) + view `user_balance`, PK, 2 FK, UNIQUE на e-mail |
| `data.sql` | 2 пользователя (Ali, Arman), 4 категории, 4 транзакции |
| Строка | `postgresql://postgres:vtcuUj%^@localhost:5432/postgres` |

Схема аккуратная для своего объёма: PK, внешние ключи, UNIQUE, view с балансом.
Но это **другая модель данных**, чем у приложения.

---

## 2. Что не сходится

| У Алибека | Нужно приложению | Почему |
|---|---|---|
| Нет `families` | `families(id, name, invite_code, currency)` | Общий бюджет семьи, вход по инвайт-коду |
| `users(user_id, full_name, email, password)` | + `family_id`, `role`, `is_active`, `password_hash` | Роли admin/member, отключение участника, настоящий хеш |
| `password = 'hashed_password'` | `pbkdf2_sha256$260000$…` | С плейсхолдером никто не войдёт в приложение |
| `categories(category_id, category_name, type)` — глобальные | + `family_id`, `kind`, `monthly_limit_cents`, `is_active` | У каждой семьи свои категории и лимиты (FR-02) |
| `transactions.amount numeric(12,2)` | `amount_cents BIGINT` | Деньги без плавающей точки (дефект D-06 у Нурбола) |
| `transaction_type 'Income'/'Expense'` | `kind 'income'/'expense'` | Единый регистр в коде и запросах |
| `description` | `note` | Имя колонки в приложении |
| Нет `created_at` | `created_at TIMESTAMP` | Аудит, сортировка |
| `user_balance` view | — | **Сохраняем**: запрос Алибека продолжит работать |

Итог: на его схеме приложение не запустится — нет семей, ролей, хешей и лимитов,
а `amount numeric` пришлось бы пересчитывать в копейки в каждом запросе.

---

## 3. Три проблемы в строке подключения

1. **Пароль с `%`.** В URL символ `%` открывает percent-encoding, поэтому `vtcuUj%^`
   ломает разбор. Правильно:
   `postgresql://postgres:vtcuUj%25%5E@localhost:5432/postgres`
   (`%` → `%25`, `^` → `%5E`).
2. **`localhost` — это его ноутбук.** С твоего компьютера база недоступна: нужен
   туннель (Tailscale, ngrok), белый IP или общий сервер лаборатории.
3. **База `postgres` — системная.** Лучше отдельная `family_budget`, чтобы не смешивать
   с системными объектами.

|---|---|---|
| **A. Схема Алибека как общая** | Дописать `families`, роли, хеши, лимиты через `ALTER TABLE`; переписать `user_balance` | Много миграций, ломает его view, роли и безопасность всё равно надо добавлять. Минус неделя |

## 5. Что сделать на этой неделе (вариант B)

Всё сводится к трём действиям: поставить PostgreSQL, один раз запустить `SETUP_POSTGRES.bat`,
проверить результат.

### Шаг 1. Поставить PostgreSQL 18 (20–30 минут)

Скачать установщик с postgresql.org (EDB), при установке:

* пароль пользователя `postgres` — записать, он понадобится;
* порт оставить `5432`;
* галочку Stack Builder в конце можно снять.

После установки сервис `postgresql-x64-18` должен быть запущен (Проверка: `services.msc`).

### Шаг 2. Прописать строку подключения

Создать в папке проекта файл `postgres_url.txt` с одной строкой:

```
postgresql://postgres:ТВОЙ_ПАРОЛЬ@localhost:5432/family_budget
```

Если в пароле есть `%`, `@`, `#` или `/` — их надо закодировать: `%` → `%25`, `@` → `%40`,
`#` → `%23`, `/` → `%2F`. Пример: пароль `vtcuUj%^` → `vtcuUj%25%5E`.

### Шаг 3. Запустить установку

Двойной клик по **`SETUP_POSTGRES.bat`**. Скрипт сам:

1. проверит и при необходимости поставит `psycopg2`;
2. создаст базу `family_budget`, если её нет;
3. загрузит `sql/schema_postgres.sql` (4 таблицы, индексы, view `user_balance`);
4. импортирует данные Алибека (2 пользователя, 4 категории, 4 транзакции);
5. покажет балансы и запишет строку подключения в `postgres_url.txt`.

Ожидаемый вывод в конце:

```
Ali     income 300000.00  expense 20000.00  balance 280000.00
Arman   income 250000.00  expense     0.00  balance 250000.00
Done. Next commands: ...
```

Если `data.sql` лежит отдельно, его можно просто перетащить мышью на `SETUP_POSTGRES.bat` —
скрипт возьмёт файл из аргумента.

### Шаг 4. Проверить

```bat
python tools\db_check.py      :: RESULT: the database matches the application schema
python selfcheck.py            :: 10/10 checks passed
START.bat                      :: в сайдбаре "Backend: PostgreSQL"
```

`START.bat` читает `postgres_url.txt` сам — переменные окружения выставлять не нужно.

### Шаг 5. Показать на паре

Войти как `ali@gmail.com` / `Demo1234` (или `arman@gmail.com`) — это пользователи из дампа
Алибека, уже в работающем приложении. Затем в pgAdmin выполнить его запрос:

```sql
SELECT * FROM user_balance;
```

Цифры совпадут с его скриншотом — это и есть доказательство, что база общая, а не две разные.

### Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| `connection refused` | Сервис PostgreSQL не запущен — `services.msc` → `postgresql-x64-18` → Запустить |
| `password authentication failed` | Неверный пароль в `postgres_url.txt` или в нём остались сырые `%`/`@` |
| `database "family_budget" does not exist` | Запустить `SETUP_POSTGRES.bat` ещё раз: он создаёт базу |
| `psycopg2` не ставится | Нет интернета или Python 3.14 без wheel — поставить Python 3.12 |
| `permission denied to create database` | Пользователь не имеет прав: использовать `postgres` или выдать `CREATEDB` |

2. Переименовать `password` → `password_hash` и сгенерировать настоящие хеши.
3. Добавить `role`, `is_active`, `monthly_limit_cents`, `kind`, `amount_cents`.
4. Переписать `user_balance` под новые колонки.
5. Переписать все запросы приложения и тесты.

Это реально, но это неделя работы и потеря части уже проверенных функций.

с такой базой вход в приложение невозможен, а раздел безопасности Абдулазиза
опирается на PBKDF2.

### Мелкие замечания для него (не блокируют)

| Замечание | Почему важно |
|---|---|
| `family_id = 1` и `user_id` захардкожены | Скрипт корректен только для чистой базы; повторный запуск упадёт на `UNIQUE` |
